# V4: the expressive Material 3 conversion

The design baseline and the order of work. Authority over `DESIGN.md`, which
predates the overhaul: where they disagree, this file wins and the `DESIGN.md`
section is marked superseded. D172, D173, D174, D175.

**Phase one is conformance: every element in the v4 language, nothing invented.**
**Phase two is polish, and only after phase one is done.** Animation, motion and
small touches. Not before: polish on an unconverted component is work thrown
away.

## 1. The baseline

`docs/screenshots/m3v4-{0..5}-light.png`, approved by the owner. **Open them.
Do not build from memory of them.** Three rounds were lost that way, D172.

What they establish:

- **One saturated block per screen, everything else quiet.** The lead is the
  section base with white type on it. Cards under it are white with a small hue
  dot. Six tinted cards of equal weight is a rainbow and gives the eye nowhere
  to land.
- **Restraint around the one colored moment is what keeps it from going dead.**
  Not more color.
- **Gold is an accent**: a chip, an icon, the capture button. Never a field.
- **Tiles are tiles**, 120 against 170. Not squares.
- **Containers, not loose rows.** Related fields sit on one surface at
  `Radius.cardLarge`. A label, a box and a gap repeated down a page is rule 15's
  uniform weight wearing a form.

## 2. Conformance, which is a command

```
python3 tools/checks/check_v4.py
```

Prints how many components are converted and what remains. It fails if a
converted component regresses, or if something on the remaining list is
actually done. **`REMAINING` in that file only ever shrinks.**

The four tells it looks for, each found on the phone:

| Tell | Meaning | The fix |
|---|---|---|
| `no-press` | tappable and silent under the finger, rule 16 | spring via `pressScale` or `openableByTap` |
| `ripple` | the other app's interaction grammar | `indication = null` plus the spring |
| `mono` | typewriter face on a word | `type.bodyS`. Mono is for figures in a column |
| `old-shape` | `Radius.card`/`fold`/`small` | `Radius.cardLarge`, or `hero` for a lead |

`ALLOWED` holds the components that keep a tell on purpose, with the reason.

## 3. Type

Two faces. **Atkinson Hyperlegible** for everything a person reads, at Bold for
display. **JetBrains Mono** for figures that line up in a column only: chart
axes, day grids, reference values, the date picker, the scrubber, a step number.

Bricolage Grotesque was removed in D174. The owner, three times: the fonts are
unnatural, they do not mix, "that font at the top is just weird". A display face
whose appeal is its quirks does not pair with a legibility face.

A bundled display face with more elegance and no quirk, in the Inter or Plus
Jakarta Sans family, is worth revisiting when there is network to fetch one.

## 4. The order of work

Component before screen. **A component fixed once is fixed on every screen that
uses it**, and screen-by-screen is what produced an overhaul three components
deep.

1. **The fourteen components** the check names. Batch them by tell, not by
   screen: all `no-press` together, then all `old-shape`.
2. **The screens that arrange them.** Not restyling, which the components now
   carry, but hierarchy: what leads, what recedes, what is grouped. `#381` is
   the forms; Projects home, the Document screen, Trail, Progress, Money,
   Chapters and Threads have not been read against section 1.
3. **The 85 screens' states**, per rule 11: empty, one, many, long text, RTL.
4. **Then polish.** `#383`.

## 5. Rules that bite here

- 11: no truncation, no blank areas, every state built.
- 14: the bar is retroactive. When it rises, everything already built comes up.
- 15: hierarchy before decoration.
- 16: everything the person touches responds.
- 21: look at it on the phone before closing anything.
- 22: pick the component from the shape of the content. Not everything is a card.
